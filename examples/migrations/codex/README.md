# Codex Memory to Memanto via OKF

Codex can distill durable knowledge from completed coding sessions, but those
memories live inside Codex's local storage. This example turns them into a
human-readable Open Knowledge Format (OKF) bundle that Memanto can dry-run,
import, recall, and export again.

The adapter is intentionally standalone and uses only the Python standard
library. It builds on Memanto's shipped `migrate okf` and `memory export --okf`
commands instead of adding a parallel import path.

## What It Reads

The preferred input is the stage-one memory database generated by Codex:

```text
~/.codex/memories_1.sqlite
```

The adapter also accepts:

- a Codex home directory and auto-discovers its memory and state databases;
- the portable JSON snapshot format emitted by `--export-source`;
- one persisted Codex `rollout-*.jsonl` file; or
- a Codex sessions directory when stage-one memories have not been generated.

For rollout fallback, only user messages and final assistant answers are read.
Developer instructions, reasoning, commentary, tool calls, and tool outputs are
excluded.

## Run the Committed Demo

Prerequisites:

- Python 3.10 or newer
- `uv`, when running from this repository, or an installed `memanto` command

From this directory:

```bash
./run.sh
```

That one command:

1. converts a real, sanitized Codex stage-one memory export to OKF;
2. runs `memanto migrate okf --dry-run`;
3. validates the source and OKF bundle against the golden recall questions; and
4. writes generated artifacts under `out/`.

No Moorcheh API key is needed for conversion or dry-run.

## Migrate Your Own Codex Memory

Close Codex first when possible so its SQLite WAL is fully checkpointed. Then:

```bash
python3 codex_to_okf.py ~/.codex \
  --output out/my-codex-okf \
  --export-source out/my-codex-source.json

memanto migrate okf out/my-codex-okf --dry-run
```

Common Codex homes are:

- macOS and Linux: `~/.codex`
- Windows: `%USERPROFILE%\.codex`
- custom installs: the directory in `CODEX_HOME`

To force the immediate rollout fallback:

```bash
python3 codex_to_okf.py ~/.codex/sessions \
  --source-format sessions \
  --output out/session-okf
```

Malformed rollout lines are skipped and counted by default. Add `--strict` to
fail with the file and line number instead.

## Complete the Live Freedom Loop

Live import and semantic recall require a free Moorcheh API key:

```bash
export MOORCHEH_API_KEY="..."
memanto agent create codex-memory-demo \
  --description "Codex memory portability demo"

MEMANTO_AGENT=codex-memory-demo ./run.sh
```

With `MEMANTO_AGENT` set, `run.sh` performs the full loop:

```text
Codex export -> OKF -> Memanto -> semantic recall -> exported OKF
```

It writes the Memanto-exported bundle and a live recall report under `out/`.
Use a fresh agent for each live run to avoid duplicate imports.

## Generate a Fresh Codex Rollout

`generate_rollout_sample.sh` runs a real, read-only Codex task against
`sample_project/` in an isolated temporary `CODEX_HOME`, then converts the
persisted rollout:

```bash
./generate_rollout_sample.sh
```

The temporary home links only to the existing Codex authentication file. It
does not copy credentials into this repository, and it is deleted on exit. The
Codex call can consume model usage.

The committed fixture goes one step further: it was produced by Codex's own
stage-one memory extraction pipeline. See [PROVENANCE.md](PROVENANCE.md) for
the exact evidence and the one timing adjustment made in the isolated demo.

## Privacy and Safety

Codex already redacts secrets during stage-one extraction. The adapter adds a
second defensive pass for:

- common API keys, bearer tokens, JWTs, private keys, and secret assignments;
- email addresses;
- macOS, Linux, and Windows home directory usernames; and
- temporary workspace paths.

Redaction counts are recorded in `migration_summary.json`. Source databases are
opened read-only. When a WAL file exists, SQLite reads it so uncheckpointed
records are not silently dropped.

Review the portable JSON and OKF output before sharing them. Pattern-based
redaction cannot recognize every application-specific secret or sensitive fact.

## Validation Artifacts

The repository includes:

- `sample_data/codex-memory-export.json`: sanitized real source export;
- `sample_output/okf-bundle/`: importable, human-inspectable OKF;
- `sample_output/recall_report.json`: source-to-OKF golden recall parity;
- `sample_output/DRY_RUN.md`: sanitized output from Memanto's dry-run;
- `sample_output/SAVINGS_REPORT.md`: an explicit, honest OKF savings result;
- `validation/golden_qa.json`: six durable project and workflow questions;
- `MAPPING.md`: field and memory-type mapping;
- `PROVENANCE.md`: source-generation evidence and limitations; and
- `tests/test_codex_okf_adapter.py`: loader, privacy, fallback, and true
  Memanto OKF round-trip coverage.

The OKF command deliberately has no provider savings report: Memanto documents
`migrate okf` as a local import with no API key and no savings report. This
showcase reports record counts, byte sizes, redactions, and recall parity rather
than inventing a token or cost saving.

## Compatibility

Tested with Codex CLI `0.145.0-alpha.30` and the current Memanto OKF loader.
Codex's local database is an internal, evolving schema. The adapter validates
the `stage1_outputs` table and required columns before reading it, preserves
optional fields when present, and offers the rollout fallback for other
versions.
