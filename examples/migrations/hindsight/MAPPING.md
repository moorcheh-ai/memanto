# Hindsight → OKF → Memanto mapping

This adapter targets the Hindsight `0.8` list-memory API and OKF `0.2`.
It keeps a replayable copy of every returned source record. Active and
invalidated memories deliberately take different paths so that historical
corrections remain auditable without becoming active facts again.

## Type mapping

| Hindsight memory class | OKF `type` | Memanto type | Rationale |
|---|---|---|---|
| `world` | `fact` | `fact` | A statement about the user, project, or outside world |
| `experience` | `event` | `event` | Something the agent did or experienced at a particular time |
| `observation` | `learning` | `learning` | A consolidated insight supported by one or more source facts |
| Unknown future class | `observation` | `observation` | Conservative fallback; the original class remains in `x_hindsight.fact_type` |

Hindsight observations start at `0.80` confidence and receive a bounded
`0.03` evidence increment for each additional proof, capped at `0.95`.
World facts use `0.90`, experiences use `0.85`, and unknown future classes
use `0.75`. These are adapter policy values, not claims that Hindsight emits
portable confidence scores.

## Field fidelity

| Hindsight source | OKF representation | Memanto import behavior |
|---|---|---|
| `id` | Canonical `resource`, `sources[].id`, `x_memanto.source_id`, `x_hindsight.id` | The canonical resource becomes `source_ref` |
| `text` | Markdown body, plus title and description previews | Imported as memory content without summary generation |
| `context` | `## Source context` and `x_hindsight.context` | Searchable memory content and preserved extension data |
| `fact_type` | Mapped `type`, tag `hindsight:<class>`, full `x_hindsight.fact_type` | Deterministic Memanto type |
| `document_id`, `chunk_id` | `x_hindsight` and readable provenance section | Preserved as supporting data |
| `date`, `mentioned_at`, `occurred_start`, `occurred_end` | `x_hindsight`; strongest timestamp also emitted as legacy `timestamp` | `timestamp` becomes Memanto `created_at` |
| `entities` | Normalized list in `x_hindsight` and readable provenance section | Searchable content and supporting data |
| `tags` | Original tags plus `source:hindsight` and class tag | Imported as Memanto tags |
| `metadata` | Full object under `x_hindsight.metadata` | Preserved in OKF; included in bounded supporting data on import |
| `proof_count` | `x_hindsight.proof_count`; contributes to observation confidence | Preserved and visible |
| consolidation and edit timestamps | Full `x_hindsight` fields | Preserved as supporting data |
| invalidation reason and timestamp | Deprecated OKF concept under `archive/invalidated/` | Intentionally outside Memanto's `memories/` import scope |

## OKF 0.2 provenance

Each concept includes:

- a canonical Hindsight memory API URL in `resource`;
- one `sources` entry pointing to that source record;
- `generated.by: memanto-hindsight-okf/1.0.0`;
- the real capture time in `generated.at`;
- `status: stable` for active records and `status: deprecated` for invalidated
  records;
- an `x_hindsight` block containing the remaining source fields;
- an `x_memanto` block for deterministic type, confidence, source, and state.

The adapter also writes the exact normalized API snapshot and its SHA-256
digest. A reviewer can replay that snapshot and compare every generated byte.

## Why invalidated memories are archived

Hindsight moves corrected facts into an invalidation archive. Importing those
records alongside current facts would silently undo Hindsight's conflict
resolution. The generated bundle therefore has two trees:

```text
hindsight-okf/
├── memories/             # active; consumed by `memanto migrate okf`
└── archive/invalidated/  # retained for ownership and audit; not imported
```

Memanto's OKF loader scopes a bundle with a `memories/` directory to that
directory, so archived corrections are not accidentally reactivated.

## Compatibility note

OKF 0.2 supersedes the old top-level `timestamp` with `generated.at`. Memanto's
current loader still reads `timestamp` to populate `created_at`, so this adapter
emits both. `generated.at` remains authoritative OKF provenance; the legacy
field is a documented compatibility bridge.

Memanto bounds the supporting-data footer it stores for unknown OKF fields.
Very large arbitrary Hindsight metadata may therefore be abbreviated inside
the live Memanto memory. The complete value is still retained in both the OKF
frontmatter and `source/hindsight-memory-snapshot.json`; the adapter does not
claim that an unbounded metadata blob fits into Memanto's bounded memory
content field.
